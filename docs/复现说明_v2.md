## 1. 总览
- 起点权重:`robbyant/lingbot-vla-v2-6b`(官方基座)。**未使用** `lingbot-vla-v2-6b-robotwin` 后训练权重。(待各训练队友书面确认起点)
- 训练数据:RoboTwin 2.0 的 Aloha-AgileX 50 个任务 × 50 条 clean 演示(共 2500 条、549,787 帧)。**未使用 randomized 数据、外部数据、仿真 rollout 数据。**
- 语言指令:只使用每条轨迹自带的 `seen` 指令池,未使用 `unseen` 指令,未用大模型生成/改写指令。
- 一份权重:50 任务联合训练(cotrain),推理只加载这一份权重;不按任务路由,无多检查点集成,无多 seed 投票。
- 训练方式:BC(监督模仿),不使用强化学习、价值/优势加权、环境交互。

## 4. 本人负责的评测与工程部分
- 评测环境:NVIDIA RTX PRO 6000 Blackwell(96GB,共用),Ubuntu 24.04,torch 2.8.0+cu128;RoboTwin @ `266f3aadf505a4f7fe9af0faa41a20f5f47cd123`,XPolicyLab 子模块 @ `c37109c`;CuRobo v0.7.8 针对 sm_120 用 CUDA 12.8 工具链重新编译;**画面降噪器使用 OptiX**(官方默认 OIDN 在该环境不可用)。评测类型:CUDA + CuRobo,`expert_check=true`。
- 适配器:新增 `policy/LingBot_VLA_V2`,只做观测格式翻译与 14 维动作拆分,不改模型代码;观测缺少指令时直接报错,**不允许退化为任务名**。
- 评测脚本增加「专家试玩结果缓存」(仅 clean 设定可用,确定性结论才缓存)。发现缓存会让 `open_laptop`、`place_object_scale`、`put_object_cabinet` 缺少 `check_success` 依赖的变量而被误判失败,**已对这三个任务关闭缓存**。(待填:最终提交的结果是否用过缓存,以及早期用缓存的结果是否已作废重测)
- 评测校准:官方发布的后训练权重(**仅作评测对照,未用于训练或提交**)在本评测环境 8 任务面板约 75%,与基线团队同任务约 84% 在误差范围内一致;点击类任务(click_bell / click_alarmclock)官方权重在本环境偏低,原因未查明,怀疑与降噪器不同有关。
- 推理参数:bf16、不 compile、单权重、无 temporal ensemble、无 action smoothing、无 replanning;`chunk=50`,`use_length` 待填(队友交接文件为 25;早期自测为 50;基线对照实验显示 25 与 50 对成绩无明显影响)。

## 6. 已知问题与如实说明
- 渲染降噪器为 OptiX,与官方默认不同,可能使画面略有差异。
- 评测偶发渲染卡死(约每几十局一次),已用守护脚本终止并重跑,不计入成绩。
- 评测期间需与他人任务共用 GPU,曾因显存不足出现分配失败,这类批次已作废重跑。
- 面板评测每任务仅 5 次,单任务误差很大。
